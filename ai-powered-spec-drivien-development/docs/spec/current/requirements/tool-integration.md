# ツール・Git 利用の要件

## 目的・対象範囲

Copilot / VS Code の既存の機能と Git を使い、独自の実行基盤を持たずに作業する。補助スクリプトは検査だけに使う。

出典: [docs/idea/intial-idea.md](../../../idea/intial-idea.md) 第8章。共通要件: [common.md](common.md)。

## 機能要件・業務ルール

| ID | 大分類 | 機能 | 要件 |
| --- | --- | --- | --- |
| REQ-TOOL-001 | CAT-GUARD 操作と記録 | FUN-TOOL-001 | ファイルの検索・読み取り・編集、ターミナルでのテスト・静的解析の実行を、Copilot / VS Code の既存の機能で行うこと。MCP や専用のサーバーを必須にしないこと。 |
| REQ-TOOL-002 | CAT-GUARD 操作と記録 | FUN-TOOL-002 | AI が行う Git の操作は、状態の確認（status・diff・log）、人の確認を得たローカルのブランチの作成・切り替え、承認と作業の区切りのローカルのコミットに限ること。push・PR・マージ・リベース・履歴の書き換え・強制的な操作・本番反映は行わないこと。コミットには案件の範囲のファイルだけを指定して含め、無関係な未コミットの変更を含めないこと。 |
| REQ-TOOL-003 | CAT-GUARD 操作と記録 | FUN-TOOL-001 | ターミナルの実行は、ホストの標準の確認に従うこと。実行するコマンドと目的を示すこと。外部サービスへの書き込み、実際の購入・送信、本番の資格情報を使った操作をしないこと。 |
| REQ-TOOL-004 | CAT-GUARD 操作と記録 | FUN-TOOL-001 | 既存の文書・コードの部分的な変更は、エディターの差分の編集で行い、全文の書き換えは新規作成と全面的な書き直しに限ること。 |
| REQ-TOOL-005 | CAT-GUARD 操作と記録 | FUN-TOOL-003 | 検査スクリプトは、検査のスキルに含めてプラグインとリポジトリ版で配り、追加の依存なしに Node.js だけで動き、ファイルを書き換えないこと。スクリプトの置き場所ではなく、実行した workspace を検査すること。利用者はエージェントに頼んで検査・要約を得られ、人はインストール先（リポジトリ版では `.github/skills/sdd-spec-check/scripts/check.mjs`）のスクリプトを workspace で直接実行することもできること。原本・変更記録の形式上の不備（REQ-SPEC-010）を検査し、変更 ID を指定すると、状態ファイル・タスク一覧・Git の履歴から案件の状況の要約（工程、状態、期限の来た質問、承認と承認後に変わった成果物、タスクの件数、次の作業）を出すこと。 |

### 提供する機能

| ID | 機能 | 入力・前提 | 結果 | 停止・対象外 | 対応 REQ | 大分類 |
| --- | --- | --- | --- | --- | --- | --- |
| FUN-TOOL-001 | 既存のツールによる編集と実行 | 承認された範囲 | 差分による編集、ホストの確認を経たコマンドの実行 | 外部への書き込みはしない | REQ-TOOL-001、REQ-TOOL-003、REQ-TOOL-004 | CAT-GUARD 操作と記録 |
| FUN-TOOL-002 | Git の利用 | 案件のブランチ、承認 | 状態の確認、確認後のブランチ作成、ローカルのコミット | push・マージ・履歴の書き換えはしない | REQ-TOOL-002 | CAT-GUARD 操作と記録 |
| FUN-TOOL-003 | 検査のスキルと検査スクリプト | 実行した workspace、任意の変更 ID | 不備の一覧と終了コード、案件の状況の要約 | ファイルを書き換えない | REQ-TOOL-005 | CAT-GUARD 操作と記録 |

## 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-TOOL-001 | 検査スクリプトの出力やコミットに秘密の値を含めないこと。 |
| NFR-TOOL-002 | 案件の状態を、Git で管理されたファイルと履歴だけから復元できること。隠れたサーバーの状態に頼らないこと。 |

## 受入条件

| ID | 対象 | 条件・期待結果 |
| --- | --- | --- |
| AC-TOOL-001 | REQ-TOOL-001 | MCP や専用のサーバーがなくても、検索・編集・テストの実行で全工程を進められる。 |
| AC-TOOL-002 | REQ-TOOL-002、NFR-COM-004 | 承認のコミットには案件のファイルだけが含まれ、無関係な変更は作業ツリーに残る。push・マージ・リベースを頼んでも実行せず、手順を案内する。 |
| AC-TOOL-003 | REQ-TOOL-003 | テストを実行する前にコマンドと目的が示され、ホストの確認を経て実行される。実サービスへの送信を伴う操作は行わない。 |
| AC-TOOL-004 | REQ-TOOL-004 | 既存の文書の1か所を直すとき、差分の編集で行われ、文書全体は出力されない。 |
| AC-TOOL-005 | REQ-TOOL-005、NFR-TOOL-002 | 依存をインストールせずに検査スクリプトが動き、プラグインのインストール先ではなく実行した workspace が検査される。エージェントに検査を頼んでも、人がインストール先のスクリプトを workspace のルートで実行しても、同じ結果が出る。実行の前後でファイルが変わらない。変更 ID を指定すると状況の要約が出て、承認の後に編集した成果物は再承認の対象として示される。 |
| AC-TOOL-006 | NFR-TOOL-001 | ダミーの秘密情報を含む文書を検査しても、出力に秘密の値が出ない。 |
