# CHG-0005 要点

- 変える箇所: 要件は変えない（置き場所は配布の設計の決まりで、利用者から見た機能・受入条件は変わらないため）。設計 DES-TOOL-001（`docs/spec/current/design/tool-integration.md`）の配布の形式・配置図・`plugin.json` の書き方・共通ルールへの相対リンク・仕様の出典を 1.0 の形式に直す。コードとガイドは、`plugins/sdd/plugin.json`（`$schema` を加え、version を上げる）、`plugins/sdd/agents/` の4つのエージェント（`com.github.copilot/agents/` に移し、本文の `../common-rules.md`・`../skills/…` の相対リンクを1段深くする）、`plugins/sdd/README.md` の構成の表、`plugins/sdd/user_guide.md` のエージェントへのリンク、`.github/plugin/marketplace.json`・`package.json` の version、`test/customization.test.mjs` を変える。
- 方針: `plugin.json` の先頭に `"$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json"` を加え、Agent Plugins 1.0 として読ませる。今の項目（`name`・`version`・`description`・`author`・`repository`・`keywords`）はすべて 1.0 のスキーマで使えるので、そのまま残す。エージェントは `git mv` で `plugins/sdd/com.github.copilot/agents/` に移し、履歴を残す。スキルは 1.0 でも標準の場所 `skills/` なので動かさない。`$schema` を付けずに従来形式のまま残す案は、GitHub Docs が新しいプラグインには 1.0 を勧めており、スキルを他のクライアントと共有しやすくなるため採らない。
- 影響: エージェントの名前・中身・工程の手順は変えない。Agent Plugins 1.0 を読めない古い VS Code・Copilot CLI では、エージェントが見つからなくなる。そのため、`plugin.json` とマーケットプレイスの version を 0.4.0 → 0.5.0 に上げる。過去の記録（`docs/spec/changes/CHG-0001`・`CHG-0002`・`CHG-0004`、`docs/idea/`）は書き換えない。
- テスト: `test/customization.test.mjs` を先に直す。エージェントのフォルダーを `com.github.copilot/agents` にし、共通ルールへのリンクを `../../common-rules.md` にし、`plugin.json` の `$schema` が 1.0 の値であることと、ルート直下に `agents/` がないことを検査に加える。今の配置で意図どおり失敗することを確かめてから移す。`npm test` と `node plugins/sdd/skills/sdd-spec-check/scripts/check.mjs` で、プラグインの中のリンク切れを含めてエラーがないことを確かめる。手動の確認として、VS Code の別の空の workspace に `plugins/sdd` を登録し、エージェントの選択に `sdd-orchestrator` が出ることと、スキル（`/sdd-workflow-status` など）が呼べることを見る（利用者に依頼する）。
- 設計の文書: `docs/spec/current/design/tool-integration.md`（DES-TOOL-001 の配布の形式を「エージェントプラグイン（Agent Plugins 1.0）」に、配置図に `com.github.copilot/agents/` を、`plugin.json` の説明に `$schema` を、共通ルールへの相対リンクを `../../common-rules.md` に、仕様の出典に GitHub Docs のプラグインのページと確認日を加える。構成のテストの記述に `$schema` の検査を加える）。`workflow-orchestration.md` のエージェントの表はファイル名だけでパスを書いていないため変えない。
