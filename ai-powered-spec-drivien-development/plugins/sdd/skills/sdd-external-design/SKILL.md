# 外部設計

入力: 承認済みの要件（窓口から渡された機能の要件文書のパスと ID）、編集してよい範囲。

1. 要件文書のうち、利用者と利用場面・対象範囲・機能要件・業務ルール・非機能要件・受入条件・未解決質問の関係する節だけを読む。期限が設計の未解決質問は引き継ぎ、回答のないまま確定しない。
2. 設計は要件文書と同じ名前の `docs/spec/current/design/<機能>.md` の「外部設計」の部に書く。対象に応じて画面・遷移・帳票・API・CLI・外部連携を選ぶ。画面がない場合に架空の UI を足さない。外部設計が不要なら、部を作らず文書の冒頭に理由を1行書いて終える。
3. 正常のほか、空・読み込み中・入力不正・権限不足・失敗・再試行を、該当するものだけ具体化し、要件と受入条件の ID に対応付ける。設計 ID は `DES-<機能>-001` とする。新しい文書や部を作るときだけ [テンプレート](templates/external-design.md) を読む。既存の文書は差分で直す。
4. 承認者の判断が必要な動き・外部契約の変更は質問として返す。要件にない動きが必要なら、設計で補わず要件定義へ戻す提案をする。

停止: 承認者の判断が必要な動きが決まらない。

出力: 変更したファイル、設計 ID と要件 ID の対応、要点、質問。
