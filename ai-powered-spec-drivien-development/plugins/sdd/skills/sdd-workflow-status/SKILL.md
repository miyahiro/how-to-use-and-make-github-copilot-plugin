# 状況確認と再開

入力: 変更 ID（分からなければ `docs/spec/changes/` のフォルダ名の一覧から候補を示して選んでもらう）。

1. [sdd-spec-check](../sdd-spec-check/SKILL.md) で変更 ID を付けて検査し、その要約を使う。必要なら `docs/spec/changes/<ID>/status.md` を読む。要件・設計・コードを個別に読まない。
2. 工程と状態、期限の来た質問、承認と再承認が必要な工程、残りの承認、タスクの件数、ブランチの一致、次の作業を短く示す。エラーや警告があればそれも示す。
3. 「記録を見せて」には、`status.md` の承認と質問の表と、`git log --oneline --grep "approve(" -- docs/spec/changes/<ID>/status.md` の結果を示す。
4. 再開を頼まれたら、ブランチが一致しない、再承認が必要、期限の来た質問がある、のどれもないことを確かめてから、`state` を `active` に戻して次の作業から続ける。続ける作業に必要なら `note.md` の関係する節を読む（状況確認だけのときは読まない）。不一致があれば、解消の方法を示して止まる。ブランチの切り替えは確認してから行う。

停止: 案件を選べない。

出力: 状況の要約、次に必要な人の判断。状況確認だけのときはファイルを変えない。
