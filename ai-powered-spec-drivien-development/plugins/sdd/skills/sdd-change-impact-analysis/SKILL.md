# 変更の影響の調査

入力: 変更の案、関係する原本・コード。

1. 変更される要件・業務ルール・外部の契約・データ・処理を特定する。検索で該当箇所を探し、関係する節とコードだけを読む。
2. 直接の依存・呼び出し・利用場面から影響を追う。根拠のない全体の見直しや無関係な調査に広げない。
3. 互換性（API・データ・設定）、移行、既存の利用者、回帰テスト、セキュリティ・性能への影響を整理する。
4. 影響を、変える原本の文書、変えるコード、追加・変更するテスト、承認し直す工程に分けて示す。仕様を変えない修正なら、その理由を示す。
5. 結果は応答で返す。保存は窓口が `status.md` か `outline.md` に要点だけ書く。

停止: 対象や依存先を確かめられない。確かめられない範囲は「未確認」と返す。

出力: 影響の一覧、回帰テストの候補、承認し直す工程、質問。
