# 壁打ち

入力: 目的、対象者、課題、制約、既存の案。前の工程の承認は不要。

1. 事実・人の意向・仮説・未決を分けて聞き取る。具体的な利用場面で確かめる。
2. 必要な候補だけを、何を提供するかの違いで比較し、価値・実現性・リスク・制約を短く示す。大きな機能追加や範囲を推測しない。
3. 採用案で提供する機能を、機能ごとに「誰が・何をできるか」の1行で人と確かめる。今回か将来かと、関係する既存の原本も示す。
4. 今の比較に必要な前提は質問にする（[sdd-clarification](../sdd-clarification/SKILL.md)）。後の工程で決めることは期限を付けて、検討を続ける。
5. 合意した内容を `docs/spec/changes/<ID>/idea.md` にまとめる。新しく作るときだけ [テンプレート](templates/idea.md) を読み、検討段階に必要な節だけを使う。会話で済む小さな案件なら `idea.md` を作らず、`status.md` の目的と範囲に、提供する機能も含めて書くだけでよい。
6. 採否、提供する機能と範囲に人が合意したら、`status.md` の `phase` を `requirements` にし、次の作業（要件定義）を示して止まる。要件定義は依頼を受けてから始める。壁打ちには承認を置かない（要件定義の承認でまとめて確かめる）。

停止: 比較に欠かせない前提が決まらない。範囲の変更に合意がない。

出力: 候補の比較、採否と理由、提供する機能の概要、範囲、質問、次の作業。
