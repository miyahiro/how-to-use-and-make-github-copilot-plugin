# GitHub Copilot Plugin 利用編の設計

入力: [利用編の要件](../requirements/plugin-usage.md)

## 外部設計

### 1. 設計対象・概要

- 対象: Copilot Chat を使い始めた開発者向けの記事の章構成と、読者がたどる操作・確認の流れ。
- 関連要件: REQ-USE-001〜009、NFR-USE-001〜002。
- 関連受入条件: AC-USE-001〜010。
- 記事は VS Code 1.145.2 を前提にする。UI 表示名・設定名・導入手順は、公開前にそのバージョンの公式資料と新しい検証環境で照合する。
- ソフトウェアの画面・帳票・公開 API を新設する設計ではないため、架空の UI、DDD モデル、ソフトウェア層は設けない。

#### 「動作確認環境」章の掲載項目

- 確認日、OS とバージョン、ローカル／リモート（Dev Container 等）の実行形態。
- VS Code と GitHub Copilot 関連拡張機能の名前・バージョン、利用した harness／クライアント。Copilot CLI を使った場合はそのバージョンも記す。
- 検証した Plugin・marketplace の版またはコミット、導入方法と導入・有効化の範囲、Workspace の事前状態。
- 環境ごとに確認した操作・結果と、未確認または動作しなかった範囲。詳細な検証記録へ対応付け、利用者からの既報告と記事作成時の再現確認を区別する。
- VS Code 1.145.2 は対象環境であり、実際に確認するまでは確認済みと記載しない。不明なバージョンや未実施の項目は推測せず「不明」「未確認」と記す。認証情報・秘密の値は掲載しない。

### 3. 外部動作・確認事項

#### DES-USE-002: 設定や導入手順が環境で異なる場合

1. 公式資料に記載された仕様と、実機で観測した結果を見出しまたは表で分離する。
2. 実機結果にはクライアント名・バージョン、Workspace 状態、操作、実際の結果を添える。
3. 不一致時は適用対象を限定して記し、一般仕様として拡張しない。再現できない結果や未確認の代替手順は「未確認」とする。
4. 記事の実行例に使う操作・設定名は公開前に対象バージョンの公式資料と照合する。CLI コマンドの仕様はこの設計では確定しない。

| 種別 | 要件・受入条件 | 確認観点 |
| --- | --- | --- |
| 設計項目 | REQ-USE-004, REQ-USE-009 / AC-USE-003, AC-USE-006, AC-USE-010 | 公式仕様・実機報告・今回の確認記録の出所が区別され、適用範囲と未確認事項が明示される。 |

#### DES-USE-004: private marketplace からの取得・導入・更新

1. 利用者は許可された GitHub アカウントで認証し、marketplace の private repository に読み取り権限があることを確認する。アクセス拒否時は導入を中断し、管理者へ権限を確認する。資格情報を記事・共有ログへ貼り付けない。
2. 認証済み環境から marketplace を取得する。marketplace 定義と参照先、Plugin の提供元・コード・設定・版・変更履歴を確認し、信頼できると判断してから導入する。
3. 非公開リポジトリを特定クライアントへ直接登録できるとは仮定しない。認証済みローカル clone を経由した登録は候補とし、対象の VS Code 1.145.2 と対象 harness／クライアントそれぞれで、公式資料に照合した方法を新しい環境で確認する。未照合の URL、manifest、CLI 構文を確定操作として記事に載せない。
4. 更新時は clone を取得元と照合して更新し、変更・版・コードを再確認したうえで、確認済みの方法で marketplace と Plugin を更新する。更新後に対象環境で利用できることを確認し、環境・版・操作・結果を記録する。

利用者の既報告として、ローカル marketplace を CLI から登録して Plugin を導入すると、Copilot CLI と VS Code の両方で利用できたとの記録がある（`docs/spec/changes/CHG-0001/note.md`）。この報告は本作業で再現確認しておらず、新規環境の検証結果や任意の private repository／クライアントの直接登録対応を示すものではない。報告された CLI の具体的な構文も公式資料と対象バージョンで照合するまでは確定手順として扱わない。

GitHub private repository のアクセス制御は取得前のアクセス範囲を制限するが、許可された利用者が取得・導入した Plugin を複製・再配布することを防ぐものではない。記事で配布元の非公開性を導入先での再配布防止保証として説明しない。

## 内部設計

### 1. 対象と作成上の方針

- これは記事の編集・事実確認方針であり、実行ソフトウェアの内部構造を定義しない。
- 機能要件を満たすため、各手順の根拠を公式資料または再現確認に結び付ける。人による新環境検証を基本とし、未実施・確認不能は成功と扱わない（NFR-USE-001, NFR-USE-002）。

### 2. Workspace 補完例

#### DES-USE-003: プロジェクト固有の作業指示を追加する例

- 例の狙い: 導入済み Plugin のファイルを変更せず、プロジェクトに固有の指示を Workspace 側に一つ追加して、既存の Plugin の利用を補う。
- 題材案: 変更内容を説明するとき、対象リポジトリの利用者が確認できるテスト実行方法を回答に含めるよう、プロジェクト固有の指示を追加する。
- 記事では、採用するファイル名・配置・指示の適用範囲を VS Code 1.145.2 の公式資料で確認してから掲載する。実際に指示を加える前後で同じ代表タスクを実行し、出力に期待した差が観測できるか新しい環境で確認する。パスや適用範囲が未確認のまま有効と断定しない。
- 既存 Plugin のキャッシュを編集しない。Workspace 側の指示が作用しない場合は未成功として記録し、代替機能を紹介するなら別途実機確認する。

### 4. 変更影響・未決事項

- ソフトウェアのデータ、認証、トランザクション、コンポーネント層は該当しない。
- 公式資料と利用者の実機報告が異なる場合、どちらかを無断で上書きせず、対象環境と出所を保ったまま記事で説明する。
- private marketplace の取得・登録・導入・更新手順、CLI の適用範囲、`.github/copilot/settings.json` の具体的な動作は記事公開前に再確認する。現時点でこれらの新規環境における確認は未実施。
